# 后台管理一期共用接口汇总

## 统计口径

- 统计范围：`接口文档/后台管理一期/01-06` 全部页面接口文档。
- **管理端内部共用**：同一「请求方法 + 路径」被 2 个及以上一期后台页面使用（见下文第一节）。
- **端管数据联动**：与 `接口文档/客户端` 共用**同一套数据库实体**（`User`、`Asset`、订单表、`LedgerEntry`、`AuditLog` 等），HTTP 路径不同，但通过 **`uid` / 订单号 / `traceId`** 对齐（见第二节，核对重点）。

---

## 一、管理端内部共用接口（仅后台）

| 排名 | 接口 | 接口功能描述 | 使用该接口页面 | 使用次数 |
| --- | --- | --- | --- | --- |
| 1 | `POST /api/admin/auth/login` | 管理员登录 | `01-登录页` 及鉴权链路 | 6+ |
| 2 | `GET /api/admin/auth/profile` | 当前管理员资料与权限 | 各鉴权页（按需） | 6+ |

> 冻结/解冻为单页接口（`02-用户管理`），路径：`POST /api/admin/users/:uid/freeze|unfreeze`。

### 1) POST /api/admin/auth/login

| 字段 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `username` | Body | string | 是 | 管理员账号（**非** C 端 `username` 混用） |
| `password` | Body | string | 是 | 管理员密钥 |
| `code` | Response | number | 是 | 业务状态码，成功 `200` |
| `message` | Response | string | 是 | 与客户端一致 |
| `data.token` | Response | string | 是 | **管理员 JWT**，写入 `admin_token` |
| `data.adminUser.username` | Response | string | 是 | 管理员账号 |
| `data.adminUser.roleCodes` | Response | array | 是 | 管理员角色 |
| `data.adminUser.permissionCodes` | Response | array | 是 | 权限码 |

### 2) GET /api/admin/auth/profile

| 字段 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `Authorization` | Header | string | 是 | `Bearer <admin_token>` |
| `data.username` | Response | string | 是 | 管理员账号 |
| `data.permissions` | Response | array | 是 | 权限码列表 |

## 二、与客户端数据联动对照（端管共用字段）

以下字段与 `接口文档/客户端/00-客户端共用接口汇总.md` 及分页面文档对齐，保证**同一业务事实**在 C 端产生、在管理端可查。

### 2.1 统一响应外壳（两端一致）

| 字段 | 客户端 | 管理端一期 | 一致性 |
| --- | --- | --- | --- |
| `code` | Response | Response | ✅ 均为业务状态码，`200` 成功 |
| `message` | Response | Response | ✅ |
| `traceId` | Response（写操作常见） | Response（写操作常见） | ✅ 同一追踪号贯穿审计 |
| `data` | Response | Response | ✅ 业务载荷 |

### 2.2 登录态（不可混用）

| 项目 | 客户端 | 管理端 | 说明 |
| --- | --- | --- | --- |
| 登录接口 | `POST /api/auth/login` | `POST /api/admin/auth/login` | ❌ 路径不同，**Token 不可互用** |
| Token 存储 | `localStorage.user` + token | `admin_token` | 分离 |
| 用户标识 | `data.user.uid` | — | 仅 C 端登录响应 |
| 冻结生效 | 登录 `423` / 交易 `403` | `POST .../freeze` 改 `User.status` | ✅ 同一 `User` 表 |

**客户端登录响应（对照 `01-登录页-Login.md`）**

| 字段 | 类型 | 管理端对应 |
| --- | --- | --- |
| `data.token` | string | 无（管理员 token 独立） |
| `data.user.uid` | string | `GET /api/admin/users` → `rows[].uid` / `?uid=` |
| `data.user.username` | string | 列表无单独字段时可查详情 |
| `data.user.realNameVerified` | boolean | 见 2.3 实名对照 |
| `data.user.status` | string | `rows[].userStatus`（文案）/ `User.status` 枚举 |

### 2.3 用户与资产（对照客户端 `GET /api/user/profile`）

**客户端接口**：`GET /api/user/profile`（`13-交易页`、`14-个人中心`）  
**管理端接口**：`GET /api/admin/users`（`02-用户管理`）

| 业务含义 | 客户端字段 (`/api/user/profile`) | 管理端字段 (`/api/admin/users`) | 库表来源 | 一致性 |
| --- | --- | --- | --- | --- |
| 用户唯一编号 | `data.uid` | `rows[].uid`、`selectedUser.uid` | `User.uid` | ✅ 主联动键 |
| 昵称 | `data.nickname` | `rows[].nickname` | `User.nickname` | ✅ |
| 实名（布尔） | `data.realNameVerified` | — | `User.realNameStatus` | ⚠️ 管理端用文案，见下表 |
| 实名（展示） | — | `rows[].realNameStatus` | 映射文案 | ⚠️ |
| 增值收益 | `data.appreciationIncome` | `selectedUser.appreciationIncome` | `Asset.appreciationIncome` | ✅ |
| 可提现本金 | `data.withdrawablePrincipal` | —（一期详情未全量展示） | 计算字段 | ⚠️ 客户端实时计算 |
| 本金余额 | `data.principalBalance` | — | 计算字段 | ⚠️ |
| 暂定/可用资金 | `assets[]` 中 balance 口径 | `rows[].cashAsset` | `Asset.cashAsset` / `tentativeAsset` | ⚠️ 见口径说明 |
| 持仓克数 | `data.goldPositions[]` | `rows[].goldHoldingGrams` | `Asset.goldHoldingGrams` | ✅ |
| 总资产 | `assets[]` total 或计算 `totalAsset` | `rows[].totalAsset` | `Asset.totalAsset`（库）vs 客户端 `暂定+市值` | ⚠️ 见口径说明 |
| 账户状态 | 隐含于登录/交易错误 | `rows[].userStatus` | `User.status` | ✅ 冻结联动 |

**实名状态映射**

| `User.realNameStatus`（库） | 客户端 `realNameVerified` | 管理端 `realNameStatus` 文案 |
| --- | --- | --- |
| `VERIFIED` | `true` | 已实名 |
| `PENDING` | `false` | 待审核 / 未实名 |
| `REJECTED` | `false` | 已拒绝 |

**总资产口径说明（验收必读）**

- C 端 `GET /api/user/profile`：`totalAsset = tentativeAsset + 行情市值`（随金价变动）。
- 管理端列表：`totalAsset` 来自 `Asset.totalAsset` 字段格式化。
- 充提、成交后两端应通过 **`LedgerEntry` + 订单落库** 同步资产；若仅 C 端展示跳动而库字段未回写，会出现短暂不一致。

### 2.7 资金流水与审计（对照 `15-金链记录`、设置安全）

| 项目 | 客户端 | 管理端一期 |
| --- | --- | --- |
| 金链公开记录 | `GET /api/public/gold-chain` | — |
| 资金流水 | 无独立 C 端管理页 | `GET /api/admin/funds` → `ledgerRows[]` |
| 审计列表 | — | `GET /api/admin/audit` |
| 链路详情 | — | `GET /api/admin/audit/trace/:traceId` |

| 联动字段 | 说明 | 一致性 |
| --- | --- | --- |
| `traceId` | 充值/提现/交易/审核写库时生成，**全链路主键** | ✅ |
| `ledgerRows[].traceId` | 与 `AuditLog.traceId`、`HashRecord.traceId` 相同 | ✅ |
| `ledgerRows[].target` | 对应 `User.uid` | ✅ |
| `hashValue` / 同步 | C 端金链 `hashValue` | 管理端 `audit.rows[].hash` | ✅ 同源 `HashRecord.sha256` |

**排查路径（运营/联调）**

1. C 端操作拿到响应 `traceId`  
2. 管理端 **资金管理 → 资金流水** 按 `traceId` 搜索  
3. 管理端 **审计追溯** 查看同 `traceId` 链路节点（含 `ledger` 节点）

## 四、已知差异与同步要求（文档核对结论）

| 编号 | 差异项 | 要求 |
| --- | --- | --- |
| D1 | 管理端 `00` 原仅列管理员登录，**未写端管联动** | 已在本文件第二节补全 |
| D2 | C 端 `realNameVerified` vs 管理端实名文案 | 联调按 2.3 映射表转换 |
| D3 | C 端 `totalAsset` 计算口径 vs `Asset.totalAsset` | 以订单+流水落库后库字段为准验收 |
| D4 | 充值「对账/异常」按钮 | 管理端 API 未封装，**不可**与 C 端 confirm 混为同一接口 |
| D5 | 提现拒绝原因 | C 端可见文案需与 `WithdrawalOrder` 拒绝原因字段二期对齐 |
| D6 | 设备管理 | C 端 `settings/security`；管理端一期未展示 `UserLoginSession` | 二期补 `GET` 管理端会话列表 |
