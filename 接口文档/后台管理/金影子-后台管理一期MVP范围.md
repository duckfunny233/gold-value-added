# 金影子 · 后台管理一期 MVP 范围说明

> **文档用途**：按业务方「七大底层能力」收敛 `frontend/admin` 一期必做页面与对接项，并明确**暂缓不做**功能，避免与《金影子-后台管理功能说明.md》全量能力混淆。  
> **工程路径**：`frontend/admin`（页面） + `backend`（`admin/*` 接口）  
> **原则**：先跑通**数据读写 + 审核闭环 + 流水落库**；运营、报表、治理、可视化一律后置。

---

## 一、七大需求与页面对照

| 序号 | 你的需求 | 一期承载页面 | 路由 | 后端域（模块） |
| --- | --- | --- | --- | --- |
| 1 | 用户相关所有**基础信息** | 用户管理（精简） | `/users` | `user` |
| 2 | 用户账户**资金余额** | 用户管理 · 资产明细；资金管理 · 订单区摘要 | `/users`、`/funds` | `user`、`fund`（`Asset`） |
| 3 | 用户**充值入账**整套流程数据同步 | 资金管理 · 充值订单 | `/funds` | `fund`（`RechargeOrder` + `LedgerEntry`） |
| 4 | 用户日常**买入/卖出**交易记录 | 交易管理（仅列表） | `/trades` | `trade`（`TradeOrder`） |
| 5 | 用户**提现申请**整套流程对接 | 资金管理 · 提现审核 | `/funds` | `fund`（`WithdrawalOrder` + 审核接口） |
| 6 | 后台**管理员权限、子账户**登录管理 | 登录页 + 权限管理（仅账号/角色） | `/login`、`/risk` | `admin-auth`（`admin/security/*`） |
| 7 | 所有**资金往来流水**留存数据库 | 资金管理 · 资金流水；审计追溯（按 trace 查链路） | `/funds`、`/audit` | `fund`（`LedgerEntry`）、`audit` |

**一期不单独开新页面**：在现有 10 个菜单里**保留 6 个**，**整页暂缓 4 个**（见文末清单）。

## 二、一期必做：按页面拆解

### 2.1 管理员登录（必做）

| 项目 | 说明 |
| --- | --- |
| **路由** | `/login` |
| **页面文件** | `LoginView.vue` |
| **必做能力** | 账号 + 密钥登录；Token 写入本地；未登录跳转登录；登录后进业务区 |
| **对接接口** | `POST /api/admin/auth/login`、`GET /api/admin/auth/profile` |
| **验收标准** | 子账户能用各自账号登录；退出/过期后无法访问 `/users` 等页 |

---

### 2.2 用户管理（必做 · 精简）

| 项目 | 说明 |
| --- | --- |
| **路由** | `/users` |
| **页面文件** | `UsersView.vue` |
| **对应需求** | ① 用户基础信息；② 账户余额 |

#### 必做功能（对接真实后端）

| 模块 | 功能点 | 接口 |
| --- | --- | --- |
| 列表 | 分页查询：UID、用户 ID、注册序号、实名状态；展示昵称、手机（脱敏）、账户状态、现金/总资产等列表字段 | `GET /api/admin/users` |
| 详情 · 概览 | 用户 UID、昵称、状态、最近交易时间等摘要 | 同上 `data.selectedUser` |
| 详情 · 注册信息 | 注册时间、渠道等**库里有则展示** | 同上 |
| 详情 · 实名信息 | **只读**展示实名状态、姓名脱敏（不做审核工作台） | 同上 + `User.realNameStatus` |
| 详情 · 资产明细 | 可用余额、冻结、持仓克数、总资产、累计盈亏等 | 同上 `selectedUser` / `Asset` |
| 管控 | **冻结 / 解冻**（影响交易、提现） | `POST /api/admin/users/:uid/freeze`、`unfreeze` |
| 关联记录（简版） | 该用户最近充值/提现/交易/审计各若干条，**仅列表只读** | `GET /api/admin/users` 的 `relatedRecords` |

#### 本页一期不做（见第四节）

踢下线设备、强制登出、重置密码、手机号验证码查看明文、生成用户报表、人工复核弹窗（非冻结必需）等。

---

### 2.3 资金管理（必做 · 核心）

| 项目 | 说明 |
| --- | --- |
| **路由** | `/funds` |
| **页面文件** | `FundsView.vue` |
| **对应需求** | ② 余额汇总；③ 充值；⑤ 提现；⑦ 流水 |

#### 必做：订单操作区（保留 `activeMainTab = orders`）

| 子 Tab | 功能点 | 接口 |
| --- | --- | --- |
| **充值订单** | 列表：单号、用户 UID、渠道、金额、状态、时间；筛选 UID/渠道/状态/时间 | `GET /api/admin/funds` 或 `GET /api/admin/funds/recharges` |
| **充值** | 状态与 C 端/自动入账逻辑一致（待处理→处理中→完成/失败）；后台**只读 + 对账态展示**；若有「标记对账/异常」且后端已支持则保留按钮 | 以 `fund` 模块实际 DTO 为准 |
| **提现订单** | 排队列表：收款信息、金额、状态、提交时间 | `GET /api/admin/funds/withdrawals` |
| **提现审核闭环** | **通过** → **拒绝（填原因）** → **标记转账完成** | `POST .../approve`、`reject`、`confirm-completed` |
| **资金流水** | 全平台 `LedgerEntry` 列表：追踪号、类型、用户、金额、余额后、时间、关联单号 | `GET /api/admin/funds` 的 `ledgerRows` |

#### 必做：与用户资产的关系

- 每笔充值成功、提现完成、买卖成交，后端必须写 **`LedgerEntry`**（已有 `fund` / `trade` / `payment` 落账逻辑，一期验收以库表为准）。
- 用户详情「资产明细」与流水 **`userId` / `traceId`** 可互查。

#### 本页一期不做

「平台总览」整 Tab（趋势图、资金池健康度、渠道分布、异常预警、阈值设置）、手工转账/补款/资产调整、渠道对账看板、提现静音提醒、批量审核（可二期）、导出报表任务。

## 四、一期整页暂缓（菜单可隐藏或置灰）

| 页面 | 路由 | 暂缓原因 |
| --- | --- | --- |
| **首页仪表盘** | `/dashboard` | 运营驾驶舱、公告、全局通知、待办聚合——非七大底层 |

## 五、已在系统中但一期明确不做的功能（按模块罗列）

### 5.1 用户管理 `/users`

- 生成用户列表报表（`POST /api/admin/reports/generate`）
- 踢下线指定设备、强制登出、重置密码（前端已有入口，**后端未齐则一律不做**）
- 手机号验证码查看完整号码
- 账户「禁用/启用」与冻结重复的高阶管控
- 跳转其他页的「深度运营」联动（保留只读关联记录即可）

### 5.2 资金管理 `/funds`

- **平台总览** Tab 全部：资金概况卡片、实时趋势图、用户资产汇总、资金池健康度、渠道分布、异常预警、预警阈值 PATCH
- 手工转账、补款、资产调整（`manual-transfer` / `manual-adjust`）
- 渠道对账摘要区块
- 提现「静音提醒」、批量通过/拒绝（可二期）
- 导出资金报表 / 报表中心任务

### 5.3 交易管理 `/trades`

- 全站停盘 / 恢复交易（`pause` / `resume`）
- 上金所交易时段同步只读区、重试同步、回填资产
- 交易统计运营卡片、生成交易报表

### 5.4 权限与风控 `/risk`（保留路由时的裁剪项）

- 更新风控规则、规则预览、定时生效、版本回滚
- 黑名单 UID、异常交易阈值展示与变更
- 风控预警列表、风控操作日志（审计页可部分替代）

### 5.5 审计追溯 `/audit`（裁剪项）

- `verify-hash`、trace 导出、审计报表任务

### 5.6 其他整页能力（对应第四节整页暂缓）

- 仪表盘：公告 CRUD、全局 HTML 公告、待处理单据、模块筛选刷新
- 排行榜：规则配置、重建、移出榜单、同步监控、排行榜报表
- 报表中心：模板管理、任务导出 Excel、多模块汇总报表
- 实名审核：批量通过/拒绝、证件大图审核流
- 系统配置：交易时段/休市/费率/注册限制/配置变更日志

### 5.7 与 C 端无关的后台附加能力

- 支付单独立管理页（`admin/payments`，前端未单独成页，一期不建）
- 新闻/公告轮播运营（仪表盘能力）
- 任何依赖 **mock / PlatformService 占位接口** 且后端未实现的图表类 API（`platform.js` 中资金趋势、健康度等）

## 七、前端改造建议（实施时注意）

1. **侧栏菜单**：一期仅展示 `用户管理`、`资金管理`、`交易管理`、`权限管理`（或仍用 `/risk`）、`审计追溯`、`登录`；其余路由可 `meta.mvpHidden: true` 或注释菜单项。  
2. **`FundsView`**：默认进入「订单操作」，隐藏「平台总览」Tab 及手工调账按钮。  
3. **`RiskView`**：仅渲染管理员账号区块；风控规则相关 DOM 用 `v-if="false"` 或拆组件延后。  
4. **统一走 `AdminService` + `apiFetch`**，停用 `PlatformService` 占位图表直至后端就绪。  
5. **接口文档**：联调时以本文第六节 + `03/04/05/07/08` 号页面文档为准；全量产品说明见《金影子-后台管理功能说明.md》。
