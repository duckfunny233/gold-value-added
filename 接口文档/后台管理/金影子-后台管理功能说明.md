# 金影子 · 后台管理系统功能说明

> **文档用途**：面向甲方（业务方、验收方）说明后台管理系统的功能范围、使用场景与操作能力。  
> **系统名称**：金影子后台管理系统  
> **技术形态**：Web 管理端（`frontend/admin`），管理员通过浏览器访问，登录后左侧导航进入各业务模块。  
> **文档版本**：与当前前端页面实现一致（2026-05）

---

## 一、系统定位

金影子后台管理系统是面向**平台运营、风控、财务与客服**的统一管理入口，用于：

- 掌握平台与用户侧核心经营数据（交易、资金、用户、排行榜等）；
- 处理需人工介入的业务（提现审核、实名认证审核、充值对账、账户管控等）；
- 配置平台规则（交易时段、费率、风控阈值、排行榜规则等）；
- 发布运营内容（公告、全局通知）；
- 在出现异常或争议时，通过**审计追溯**与**报表导出**留痕、举证。

用户端 App 的日常交易、充值等行为在 C 端完成；本系统负责**监管、审批、配置与应急处置**（如全站停盘、冻结账户）。

## 三、各页面功能说明

### 3.1 管理员登录

| 项目     | 说明 |
| -------- | ---- |
| **路由** | `/login` |
| **定位** | 系统入口，仅授权管理员可进入后台。 |
| **能力** | 输入管理员**账号**与**密钥**登录；登录成功后跳转首页仪表盘，会话信息本地保存，未登录访问业务页将跳转登录页。 |

**业务价值**：区分 C 端用户与后台操作人员，保障管理操作可追溯（与审计、风控日志联动）。

---

### 3.2 首页仪表盘

| 项目     | 说明 |
| -------- | ---- |
| **路由** | `/dashboard` |
| **定位** | 运营「驾驶舱」，一屏查看平台状态与待办。 |

#### 主要功能

1. **数据筛选与刷新**  
   - 按日期范围（今日 / 近 7 天 / 近 30 天）、所属模块（资金 / 交易 / 风控 / 审计）、严重级别筛选后查询。  
   - 展示**当前交易状态**（交易正常 / 停盘中）。  
   - 支持一键刷新仪表盘。

2. **统计卡片**  
   - 展示后台汇总的关键指标（具体指标项由后端返回，如交易量、待办数量等）。

3. **待处理单据**  
   - 列表展示跨模块待办：单号、模块、事项、责任人、级别、时间，便于运营按优先级跟进。

4. **公告管理**  
   - 查看公告列表（标题、状态、发布时间、是否轮巡展示）。  
   - **发布 / 编辑 / 删除**平台自建公告（发布后进入用户端首页轮播展示）。  
   - 外部新闻流同步的公告为**只读**，不可在后台编辑删除。

5. **最近事件速览**  
   - 展示近期关键操作事件（模块、详情、时间），可跳转「审计追溯」查看完整链路。

6. **全局公告编辑**  
   - 开关「启用全局公告」，编辑公告正文（支持 HTML），可预览效果并保存；用于全站弹层类通知场景。

**典型场景**：每日晨会前打开仪表盘掌握待办与交易状态；活动前发布/更新首页公告。

---

### 3.3 用户管理

| 项目     | 说明 |
| -------- | ---- |
| **路由** | `/users` |
| **定位** | 全平台 C 端用户的查询、详情查看与账户级管控中心。 |

#### 主要功能

1. **用户检索**  
   - 支持用户 ID、用户 UID、注册序号、实名状态等条件筛选；分页浏览用户列表。  
   - 列表字段含：昵称、实名/充值/提现状态、现金资产、总资产、账户状态等。  
   - 支持复制用户 ID；可**生成用户列表报表**（任务在报表中心下载）。

2. **账户管控（列表与详情内）**  
   - **冻结 / 解冻**：冻结后用户无法交易、提现。  
   - **重置密码**：用户需通过手机号重新设置密码。  
   - **强制登出**：立即终止当前会话。

3. **用户详情（右侧抽屉，多标签）**  
   | 标签       | 内容说明 |
   | ---------- | -------- |
   | 概览       | 增值收益、收款摘要、风险状态、最近交易时间、最近追踪号等 |
   | 注册信息   | 注册时间、渠道、IP、设备；手机号脱敏展示，验证后可查看完整号码 |
   | 实名信息   | 姓名、脱敏身份证号、认证状态、收款方式；可跳转实名审核页 |
   | 资产明细   | 可用余额、冻结金额、持仓市值、累计盈亏、黄金持有克数、总资产等 |
   | 登录设备   | 设备名、IP、最近登录时间；支持**踢下线**指定设备 |
   | 操作记录   | 该用户相关后台/系统操作日志摘要 |
   | 账户控制   | 禁用/启用、重置密码、强制登出等集中入口 |

4. **关联记录**  
   - 按用户查看充值、提现、交易、审计四类关联记录摘要，并可一键跳转至资金管理、交易管理、审计追溯对应页面。

**典型场景**：客诉时查用户资产与实名；发现异常账户冻结并踢出多端登录；导出用户清单做运营分析。

### 3.4 交易管理

| 项目     | 说明 |
| -------- | ---- |
| **路由** | `/trades` |
| **定位** | 黄金买卖订单的查询、监控与**全站交易开关**控制。 |

#### 主要功能

1. **交易状态与统计**  
   - 页头展示全站交易状态（正常 / 停盘）。  
   - 统计卡片展示交易量、金额等汇总（由后端提供）。

2. **交易列表查询**  
   - 按交易号、类型（买入/卖出）、用户 UID、交易状态、同步状态、时间范围筛选。  
   - 列表含：用户、金额、克数、状态、同步状态、创建时间等；点击行可查看选中交易。

3. **全站停盘 / 恢复交易**（应急能力）  
   - **全站停盘**：所有用户无法提交买卖单，可填写停盘原因（记入操作日志）。  
   - **恢复交易**：恢复正常买卖。  
   - 停盘/恢复按钮与当前状态互锁，防止误操作。

4. **上金所交易时段同步（只读）**  
   - 展示同步来源、同步状态、当前时段、下一开盘时间。  
   - 展示按日期的交易时段表（自动同步结果，**后台不提供手动改时段**，避免与交易所规则冲突）。  
   - 交易关闭时段用户端自动禁止提交买卖。

5. **报表**  
   - 可按筛选条件生成交易流水报表，至报表中心下载。

**典型场景**：行情异常或系统故障时紧急停盘；客诉时按 UID/交易号查单笔订单；核对与上金所时段是否一致。

### 3.5 资金管理

| 项目     | 说明 |
| -------- | ---- |
| **路由** | `/funds` |
| **定位** | 充值、提现全生命周期管理，以及平台级资金健康度监控。 |

页面分为两大模块：**订单操作**、**平台总览**。

#### 3.5.1 订单操作

1. **统一筛选**  
   - 订单类型（充值/提现）、用户 UID、支付渠道（微信/支付宝/银行卡）、订单状态、时间范围。  
   - 支持查询、导出资金数据（经报表任务）。

2. **充值订单**  
   - 说明：充值一般为** 24 小时自动到账**，本模块侧重**对账与异常标记**，无人工「审核通过」按钮。  
   - 列表：订单号、用户、渠道、金额、状态、时间等。  
   - 操作：**查看详情**；对「对账中」订单可标记**已对账**或**异常**。

3. **提现订单（人工审核核心）**  
   - 按提交时间排队展示，含收款信息、审核状态、提醒状态。  
   - 单条操作：**通过**、**拒绝**（需填原因）、**标记转账完成**、**静音提醒**。  
   - **批量通过 / 批量拒绝**（勾选多条）。  
   - 详情弹窗内可完成审核与完成确认。

4. **补款与资产调整（高权限）**  
   | 操作       | 说明 |
   | ---------- | ---- |
   | 手工转账   | 对指定用户加款或减款，需填写 UID、金额、方向、原因 |
   | 补款处理   | 异常场景下为用户补款（增加方向） |
   | 资产调整   | 手工调整用户资产，需记录操作人与原因 |
   - 所有变更写入**资金流水审计**列表（追踪号、类型、目标用户、金额、操作人、时间）。

5. **渠道对账**  
   - 展示微信、支付宝、银行卡等渠道对账摘要信息。

#### 3.5.2 平台总览

1. **资金概况卡片**  
   - 累计充值、累计提现、平台当前余额、冻结金额等。

2. **实时资金流动趋势图**  
   - 当日充值与提现曲线对比，辅助判断资金进出是否异常。

3. **用户资产汇总**  
   - 总用户数、总持仓市值、总可用余额。

4. **资金池健康度**  
   - 流动性比率、风险准备金比例、健康状态（健康 / 预警 / 危险）。

5. **渠道资金分布**  
   - 各支付渠道余额及占比。

6. **异常资金预警**  
   - 大额充值、大额提现等异动列表。

7. **预警设置**  
   - 可配置：大额充值阈值、大额提现阈值、资金快速变动百分比等。

**典型场景**：财务每日处理提现审核；对账发现充值异常标为异常单；管理层查看平台总览与资金池健康；大额异动调整预警阈值。

### 3.6 排行榜治理

| 项目     | 说明 |
| -------- | ---- |
| **路由** | `/leaderboard` |
| **定位** | 用户端「排行榜」数据的规则配置、榜单维护与作弊治理。 |

#### 主要功能

1. **榜单查询**  
   - 按用户 UID、排序规则（黄金克数 / 总资产）、同步状态、时间范围筛选。  
   - 列表：排名、UID、昵称、持有黄金克数、总资产、同步状态、更新时间。

2. **规则参数（当前生效展示）**  
   - 排行周期（日榜 / 周榜 / 月榜）、黄金权重、资产权重、上榜门槛、规则版本与更新时间。

3. **治理操作**  
   | 操作           | 说明 |
   | -------------- | ---- |
   | 更新排序规则   | 切换按克数或总资产排序并生效 |
   | 重建排行榜     | 触发全量重算任务 |
   | 规则配置       | 配置周期、权重、门槛；支持**预览**新规则下榜单效果后再保存 |
   | 标记异常用户   | 对可疑用户「从榜单移除」或「标记异常」 |

4. **同步监控**  
   - 侧栏展示榜单同步/重排相关监控指标。

5. **报表**  
   - 可导出排行榜数据报表。

**典型场景**：活动期调整权重与门槛；发现刷榜用户移出榜单；规则变更前预览再上线。

### 3.7 权限与风控

| 项目     | 说明 |
| -------- | ---- |
| **路由** | `/risk` |
| **定位** | 后台管理员账号管理、平台级风控规则配置及变更留痕。 |

#### 主要功能

1. **筛选查询**  
   - 按 UID（用于筛管理员）、角色类型（平台管理员 / 风控 / 审计）、风险类型、预警级别、时间范围查询。

2. **当前风控规则展示**  
   - 提现拦截开关、单笔提现上限、日提现上限、异常交易阈值；含规则版本号与更新时间。

3. **更新风控规则**  
   - 修改上述参数；支持**立即生效**或**定时生效**。  
   - 保存前展示**变更预览**；若单笔/日提现上限变动超过约 30%，需**二次确认**（重大变更保护）。  
   - 支持**规则回滚**到历史版本。

4. **管理员列表**  
   - 展示后台账号：登录名、显示名称、角色、权限数量、状态（启用/冻结）、最近登录时间。  
   - **增加管理员**：设置账号、密钥、显示名、角色（从系统角色列表选择）。

5. **风控日志**  
   - 记录规则调整、权限变更等：操作事项、操作人、结果、追踪号、时间。

**典型场景**：大促前调高提现限额；风险升高时开启提现拦截；为新入职运营开通管理员账号；争议时查规则变更历史。

### 3.8 审计追溯

| 项目     | 说明 |
| -------- | ---- |
| **路由** | `/audit` |
| **定位** | 以「追踪号（traceId）」串联资金、交易、风控、后台操作等全链路日志，满足合规与问题排查。 |

#### 主要功能

1. **日志检索**  
   - 按追踪号、用户 UID、所属模块、事件类型（充值/提现/买卖/后台操作）、时间范围查询。  
   - 列表：追踪号、模块、事件类型、UID、业务单号、哈希值、创建时间；分页浏览。

2. **链路详情**  
   - 点击某条记录，右侧展示该 trace 的链路节点摘要（节点类型、模块、动作、关联单号、时间等）。

3. **报表**  
   - 按当前筛选条件生成审计报表，至报表中心导出。

**设计说明**：同一追踪号应能串联一笔业务从发起到落账、风控拦截、同步等各环节，便于甲方验收「操作可追溯、不可抵赖」类需求（具体哈希校验能力以后端实现为准）。

**典型场景**：用户投诉「钱未到账」时按 UID 或单号查 trace；监管检查导出某时间段审计报表。

---

### 3.9 报表中心

| 项目     | 说明 |
| -------- | ---- |
| **路由** | `/reports` |
| **定位** | 各业务模块触发的**异步报表任务**统一查看与下载入口。 |

#### 主要功能

1. **任务筛选**  
   - 报表名称关键词、来源模块（用户管理 / 排行榜 / 交易 / 资金等）、任务状态（待生成 / 生成中 / 已完成 / 失败）、生成时间范围。

2. **生成报表**  
   - 按筛选条件创建新报表任务（默认 CSV 等格式由后端定义）。

3. **导出下载**  
   - 在导出列表中选中一条任务，支持导出 **CSV** 或 **Excel** 到本地。

4. **任务列表字段**  
   - 报表名称、生成时间、生成人、汇总规则、来源模块、状态。

**与其他模块关系**：用户管理、交易管理、资金管理、排行榜、审计等页面的「生成报表」均汇聚到此下载，避免各页重复实现导出逻辑。

**典型场景**：财务月底导出交易与资金报表；运营导出用户清单；审计导出操作日志。

### 3.10 实名认证审核

| 项目     | 说明 |
| -------- | ---- |
| **路由** | `/realname-audit` |
| **定位** | 用户提交实名认证材料的人工审核工作台（合规必备）。 |

#### 主要功能

1. **列表检索**  
   - 审核状态（待审核 / 已通过 / 已拒绝）、关键词（用户 ID / 姓名 / 身份证号）、提交时间范围、操作人。  
   - 分页列表：用户 ID、姓名、身份证号、提交时间、状态。

2. **单条审核**  
   - 待审核记录可**通过**或**拒绝**，可填写审核备注。  
   - **批量通过 / 批量拒绝**当前页待审核项。

3. **认证详情（右侧）**  
   - 用户基本信息、手机号（脱敏）、注册信息。  
   - **身份证正反面照片**缩略图，点击可大图预览。  
   - **审核记录**：历史操作时间、通过/拒绝、操作人、备注。

**与用户管理联动**：用户详情「实名信息」标签可跳转本页处理同一用户。

**典型场景**：新用户实名 backlog 清理；身份证照片不清晰拒绝并备注原因。

### 3.11 系统配置

| 项目     | 说明 |
| -------- | ---- |
| **路由** | `/system-config` |
| **定位** | 平台级基础参数配置中心（影响交易时间、费率、注册风控等）。 |

#### 配置分类（标签页）

| 标签       | 配置内容 |
| ---------- | -------- |
| 交易时段   | 日盘开盘/收盘、午休起止、夜盘开盘/收盘 |
| 休市规则   | 是否周末休市；节假日休市日期列表（可增删） |
| 费率配置   | 充值手续费率、提现手续费率、交易佣金率（%） |
| 注册限制   | 同一 IP 注册账号数量上限 |
| 变更日志   | 配置项修改历史：时间、操作人、配置项、旧值、新值 |

保存前二次确认，防止误改影响线上交易与资金安全。

**说明**：用户端交易时段还可能受「上金所自动同步」约束（见交易管理页只读展示）；系统配置与同步结果的关系以后端策略为准。

**典型场景**：国庆休市批量添加节假日；调整交易佣金率；限制恶意注册 IP。

## 四、关键业务流程（甲方视角）

### 4.1 用户提现流程（后台侧）

```text
用户 App 发起提现
    → 资金管理 · 提现队列（待审核）
    → 财务/运营：审核通过 → 线下/渠道转账 → 标记「转账完成」
              或：拒绝（填写原因，用户可见）
    → 全程产生追踪号，可在审计追溯、资金流水中查询
```

### 4.2 实名认证流程（后台侧）

```text
用户 App 提交身份证与信息
    → 实名认证审核 · 待审核列表
    → 审核员查看证件照 → 通过 / 拒绝（备注）
    → 用户管理 · 实名状态同步更新
```

### 4.3 应急停盘流程

```text
交易管理 · 全站停盘（填写原因）
    → 全站状态变为「停盘中」（仪表盘同步展示）
    → 用户端无法下单
    → 故障恢复后 · 恢复交易
```

### 4.4 异常账户处置流程

```text
用户管理 · 冻结账户 + 强制登出 + 踢下线设备
    → 权限与风控规则（如提现拦截）叠加生效
    → 审计追溯可查操作链路
```

## 五、权限与安全说明（验收参考）

| 能力           | 说明 |
| -------------- | ---- |
| 登录鉴权       | 未登录无法访问业务页；Token 过期需重新登录 |
| 敏感信息脱敏   | 手机号、身份证号、银行卡号等在列表/详情中默认脱敏 |
| 高敏操作确认   | 冻结、停盘、拒绝提现、规则重大变更等需弹窗二次确认 |
| 操作留痕       | 资金手工调整、风控规则变更、配置修改等要求有日志/追踪号 |
| 角色分工       | 建议甲方按「超级管理员 / 财务 / 运营 / 风控 / 审计只读」分配后台账号（具体角色以后端权限配置为准） |
