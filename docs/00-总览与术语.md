# 总览与术语

## 1. 文档目的

本套文档用于统一金链·GYC 当前版本的产品规则、后台模块职责、前后端接口、系统监控与审计追溯口径。当前版本以用户最终确认的模块功能、数据归属和开发顺序作为唯一规则来源。

## 2. 项目六件套

- `00-总览与术语.md`：统一版本和术语
- `01-业务规则与账本模型.md`：核心业务规则与账本边界
- `02-系统架构（前台+后台+账本）.md`：模块架构与数据流
- `03-后台管理系统功能清单.md`：后台功能与数据归属
- `04-子代理拆分方案.md`：实施拆分与并行边界
- `05-MCP与技能建议.md`：规则校验与联调建议

## 3. 当前版本总规则

1. UID 是充值、提现、交易、资金核对、审计追踪的统一业务主键。
2. 充值 24 小时自动到账，支付成功后自动写入资金管理并同步 `暂定资产 + 总资产`，无需人工审核。
3. 提现仅交易时间可发起，提交后立即冻结金额并先扣减 `暂定资产 + 总资产`，后台线下转账后点击确认完成，不得二次扣款。
4. 交易管理覆盖买入和卖出，撮合遵循价格优先、时间优先，且必须写入代码。
5. 交易管理负责全站停盘、恢复交易和交易同步重试；交易时段必须自动同步上金所官方开休盘，无需人工配置固定时段。
6. 首页仪表盘负责全局总览、待办提醒、系统监控、实时事件流、规则提醒和公告轮播管理。
7. 公告由后台发布，前端首页轮巡展示。
8. 审计追溯负责 `traceId` 全链路日志和 64 位 SHA-256 哈希防伪追踪。
9. 每笔交易和每笔资产变动的哈希都要同步写入半公开金链。
10. 本地开发阶段必须先用假数据跑通前端与哈希规则，再接真实数据。
11. 用户提交提现后，后台立即语音播报提醒并持续响铃，进入订单详情或手动静音后停止。

## 4. 核心术语

- `uid`：业务唯一标识，用于充值、提现、交易、资产核对和对外业务追踪。
- `sequenceNo`：注册序号展示字段，当前默认与 UID 口径一致。
- `tentativeAsset`：暂定资产，充值自动到账后首先进入的资产口径。
- `cashAsset`：现金资产口径，用于后续资金管理和资产展示。
- `goldHoldingGrams`：用户当前持有黄金克数。
- `tradeSyncStatus`：交易数据与金链侧同步状态。
- `traceId`：全链路追踪号，用于把前台请求、后台处理、资金变动、审计日志串起来。
- `assetHash`：资产变动哈希存证，算法固定为 SHA-256，输出固定 64 位字符串。
- `semiPublicChain`：半公开金链，用于同步哈希防伪标识和关键追踪数据。
- `tradingSession`：交易时段同步状态，来源固定为上金所官方交易时段（Asia/Shanghai）。
- `sgeCalendarSync`：上金所交易日历同步状态，负责周末、法定节假日和夜盘跨日时段自动开休盘控制。
- `withdrawFrozenAmount`：提现冻结金额，用户提交提现即写入，用于防止重复提现和重复扣款。
- `withdrawAlertStatus`：提现语音提醒状态，取值建议为 `ringing`、`muted`、`stopped`。
- `dashboardEventStream`：仪表盘实时事件流，展示全链路操作追踪。

## 5. 强约束

1. 不得把 UID 替换成昵称、手机号作为资金主检索字段。
2. 不得继续实现“充值人工审核确认到账”的旧逻辑。
3. 不得把交易管理缩减为只支持买入。
4. 不得绕开交易时间控制和全站停盘开关。
5. 不得把公告发布能力放到仪表盘之外的主模块中。
6. 不得省略 `traceId`、同步状态或哈希存证的追踪链路。
7. 不得在交易时间外放行买卖或提现发起。
8. 不得省略 SHA-256 哈希写入和半公开金链同步。

## 6. 开发顺序

1. 先按既定模块完成前端页面结构、字段和数据归属。
2. 本地开发阶段先用假数据跑通全流程。
3. SHA-256 哈希规则必须在本地开发阶段同步写入代码。
4. 全流程跑通后，再对接服务器、域名和真实数据。
5. 此版本为最终定稿，代码开发后不再做结构/规则大改。
