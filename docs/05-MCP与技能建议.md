# MCP 与技能建议

## 1. 使用目标

本文件用于约束“后台模块分工、数据归属、接口口径、联调验收”四类信息保持一致，避免同一业务在不同文档里出现不同归属。

## 2. 必做联动项

当以下任一规则变动时，必须同步更新六件套、OpenAPI、前后端 README、后台页面文档和 admin-api 文档：

1. 充值是否为 24 小时自动入账
2. 提现审核流、提交即冻结扣减、到账确认不二次扣款
3. 提现语音提醒触发与停止规则
4. 提现是否仅交易时间可发起
5. 交易是否支持买卖、撮合规则、交易时间控制
6. 仪表盘的待办、监控、事件流、公告轮播职责
7. 公告是否为前端轮巡展示
8. SHA-256 哈希长度、归属和半公开金链同步规则
9. 用户管理和资金管理的边界
10. 排行榜排序规则和治理职责
11. 权限与风控的拦截范围
12. `traceId` 和哈希存证范围

## 3. 校验建议

### 3.1 规则校验

1. 检查资金管理文档是否明确写明“充值 24 小时自动到账，无需审核”。
2. 检查提现规则是否明确写明“仅交易时间可发起”。
3. 检查提现规则是否写明“提交即冻结暂定资产并同步扣减总资产，确认完成不得二次扣款”。
4. 检查提现规则是否写明“新单触发语音持续提醒，进入订单或手动静音后停止”。
5. 检查交易管理文档是否明确写明“买卖自动撮合，且价格优先、时间优先写入代码”。
6. 检查仪表盘文档是否包含公告轮播、前端轮巡展示和系统监控。
7. 检查审计文档是否明确写明“64 位 SHA-256 哈希 + 半公开金链同步”。
8. 检查所有后台模块是否写清数据来源。

### 3.2 接口校验

1. 充值接口必须保留自动入账和对账语义，不应再要求人工确认入账。
2. 交易接口需要覆盖买单、卖单、同步重试和交易时间配置。
3. 提现接口需要体现“仅交易时间可发起、提交即冻结、确认完成不二次扣款、拒绝解冻回补”的约束。
4. 提现接口需要体现“语音提醒状态与停止原因”字段或状态查询能力。
5. 审计接口必须支持按 `traceId` 查询全链路记录，并关联 64 位哈希。
6. 仪表盘接口需要包含核心指标、公告和事件流。

### 3.3 联调校验

1. 充值成功后，前台资产与后台资金管理对账视图同步刷新。
2. AU9999 行情每 3 到 4 秒能自动更新。
3. 买卖撮合后，成交状态、同步状态和资产自动变化。
4. 冻结用户后，其买卖、提现等动作立即被拦截。
5. 停盘后，所有买卖入口立即失效。
6. 非交易时间，买卖和提现发起都被拦截。
7. 公告发布后，前端首页轮巡展示。
8. 哈希在本地假数据链路中就能生成并校验。
9. 提现提交后用户资产与后台订单状态秒级同步，且后台语音提醒立即响起。
10. 提现确认完成后仅订单完结，不发生二次扣减。

## 4. 风险提示

1. 如果仍保留“充值人工审核”旧逻辑，会直接和当前资金管理规则冲突。
2. 如果交易管理继续只做买入，会和当前模块定位冲突。
3. 如果交易时间控制只做展示不做拦截，会导致验收失败。
4. 如果没有 `traceId` 全链路追踪和 SHA-256 哈希同步，审计追溯模块无法完成防伪溯源。
5. 如果“提交即冻结扣减”和“确认完成不二次扣减”未写死，极易出现重复扣款风险。
6. 如果语音提醒没有持续机制或停止条件不明确，提现处理可能出现漏单。
