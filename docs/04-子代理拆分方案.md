# 子代理拆分方案

## 1. 目标

围绕最终确认的八大后台模块，把文档、接口、前台、后台和后端实现拆成清晰可并行推进的交付面，避免数据归属混乱。

## 2. 拆分角色

### Agent A：业务规则与账本

负责：UID、充值 24 小时自动入账、提现提交即冻结扣减与确认完成、买卖撮合入账、交易时间控制、SHA-256 哈希与 `traceId`

交付物：

1. `docs/01-业务规则与账本模型.md`
2. `backend/README.md`

### Agent B：仪表盘与系统监控

负责：核心指标、待办列表、系统监控、事件流、规则提醒、公告轮播与前端轮巡展示

交付物：

1. `frontend/admin/页面功能-首页仪表盘.md`
2. `admin-api-首页仪表盘.md`

### Agent C：用户与资金域

负责：用户管理、充值对账、提现排队与语音提醒、提现确认完成、补款转账、资产调整、批量校验

交付物：

1. `frontend/admin/页面功能-用户管理.md`
2. `frontend/admin/页面功能-资金管理.md`
3. `admin-api-用户管理.md`
4. `admin-api-资金管理.md`

### Agent D：交易与排行榜域

负责：买卖交易管理、撮合监控、交易时间控制、排行榜重排和同步治理

交付物：

1. `frontend/admin/页面功能-交易管理.md`
2. `frontend/admin/页面功能-排行榜治理.md`
3. `admin-api-交易管理.md`
4. `admin-api-排行榜治理.md`

### Agent E：风控与审计域

负责：角色权限、冻结拦截、提现拦截、风险预警、全链路审计追溯、半公开金链哈希校验

交付物：

1. `frontend/admin/页面功能-权限与风控.md`
2. `frontend/admin/页面功能-审计追溯.md`
3. `admin-api-权限与风控.md`
4. `admin-api-审计追溯.md`

### Agent F：报表与联调验收

负责：报表中心、运营统计、自定义导出、多模块一致性验收，以及“前端假数据跑通 -> 本地哈希实现 -> 真实数据接入”开发顺序校验

交付物：

1. `frontend/admin/页面功能-报表中心.md`
2. `admin-api-报表中心.md`
3. 联调用例与验收清单

## 3. 并行边界

1. 业务规则与账本口径由 Agent A 先锁定，其他角色只能跟随，不得改口径。
2. 每个 Agent 只对自己负责的数据域写规则和接口，不跨域发明新数据归属。
3. 审计和报表只能消费上游模块数据，不反向修改业务流程。

## 4. 完成标准

1. 八大后台模块职责与数据归属一致。
2. 文档、页面说明、接口说明、OpenAPI 口径一致。
3. 自动充值、提现冻结与确认完成、提现语音提醒、自动撮合、交易时间控制、公告轮巡、SHA-256 哈希七条关键链路可完整验收。

## 5. 开发顺序

1. 先按既定模块完成前端页面结构、字段和归属。
2. 本地开发环境先用假数据跑通全流程。
3. SHA-256 哈希规则在本地开发阶段同步写入代码，不后置。
4. 全部跑通后，再对接服务器、域名和真实数据。
5. 此版本为最终定稿，代码开发后不再做结构/规则大改。
