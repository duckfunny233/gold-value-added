# 金链·GYC 用户端说明

## 1. 用户端目标

`frontend/app` 对应用户端 App，当前版本主要围绕充值、提现、买卖交易、行情展示和首页公告轮播展开。

## 2. 当前业务口径

1. 注册成功后展示 UID。
2. 充值数据按 24 小时自动到账处理，自动写入资金管理并同步 `暂定资产 + 总资产`，无人工审核等待。
3. 提现申请仅交易时间可发起，提交后立即冻结金额并实时扣减暂定资产、同步扣减总资产，进入后台人工转账确认流。
4. 交易支持买入和卖出。
5. 买卖撮合由系统自动完成，且价格优先、时间优先逻辑必须写入代码。
6. 非交易时间禁止买卖。
7. 首页公告轮播由后台仪表盘发布后按轮巡方式自动展示。
8. AU9999 行情每 3 到 4 秒刷新一次，价格精度 0.01 元/克。
9. 每笔交易和每笔资产变动的 64 位 SHA-256 哈希在本地开发阶段就要生成。

## 3. 前台页面要点

### 3.1 首页

1. 展示公告轮播
2. 公告按轮巡方式自动切换
3. 展示黄金参考价
4. 展示核心资产摘要

### 3.2 充值与提现

1. 充值提交后直接进入自动入账链路
2. 提现提交前先校验当前是否处于交易时间
3. 提现提交后立即刷新冻结结果和资产变化，展示排队与人工确认状态

### 3.3 交易页

1. 支持买单和卖单
2. 展示交易时间状态
3. 非交易时间明确禁止下单
4. 保留现有 K 线组件

## 4. 开发顺序

1. 先完成前端页面结构和字段归属
2. 本地用假数据跑通充值、提现、买卖、公告、哈希全流程
3. 之后再对接服务器和真实数据

## 5. 前端禁止项

1. 不得继续把充值做成人工审核等待页面。
2. 不得把交易页限制成只支持买入。
3. 不得忽略交易时间控制状态和提现交易时间限制。
4. 不得漏掉首页公告轮巡展示。
5. 不得把哈希生成放到真实环境阶段才实现。
