# 金链·GYC 项目总览

本仓库用于落地“金链·GYC 法币锚定金银结算系统”当前版本需求。当前版本文档已经按最终定稿重构，前端、后台、后端必须统一按本套文档开发，不再调整模块归属。

## 当前版本核心规则

1. 用户注册成功后，系统生成唯一、固定不变的 UID，充值、提现、资金核对、交易追踪全部以 UID 为主索引。
2. 充值数据覆盖微信、支付宝、银行卡三类渠道，按 24 小时自动到账处理，自动写入资金管理模块并同步 `暂定资产 + 总资产`，无需人工审核。
3. 提现数据统一进入资金管理模块，仅允许在交易时间内发起；用户提交后立即冻结提现金额并从 `暂定资产` 扣除，同时同步扣减 `总资产`，由后台线下转账后点击确认完成，不得二次扣款。
4. 交易管理覆盖买入和卖出全流程，交易数据自动撮合，无需人工干预。
5. 撮合规则必须写入代码，并严格遵循价格优先、时间优先：高买先成交，同价按提交时间先后成交。
6. 交易管理模块负责全站停盘/恢复和交易时间控制，非交易时间禁止买卖。
7. 行情继续使用 AU9999，刷新频率 3 到 4 秒，价格精度 0.01 元/克，现有 K 线组件继续保留。
8. 首页仪表盘承载公告轮播发布、系统监控、实时事件流、规则提醒和核心待办；前端首页按轮巡方式展示公告。
9. 用户管理、交易管理、资金管理、排行榜治理、权限与风控、审计追溯、报表中心按最终分工独立负责对应数据域。
10. 每笔交易和每笔资产变动都必须生成 64 位 SHA-256 哈希值，同步写入半公开金链，并保留 `traceId` 和后台审计链路。
11. 用户提交提现后，后台必须立即触发语音播报持续提醒；订单按提交时间自动排队，工作人员进入订单或手动静音后停止播报。

## 开发顺序

1. 先按此结构完成前端页面、本地字段和模块归属。
2. 本地开发环境先用假数据跑通全流程。
3. SHA-256 哈希规则必须在本地开发阶段同步实现，不后置。
4. 全部跑通后，再对接服务器、域名和真实数据。

## 开发约束

1. 文档中出现“必须”“禁止”“无需人工审核”“人工审核”的表述，一律视为强约束。
2. 充值已改为 24 小时自动入账，仅做对账查看，不得继续实现人工充值审核流。
3. 交易已改为买卖双向撮合，不得继续按“只支持买入”实现。
4. 交易时间控制和全站停盘都必须真实生效，不能只做展示开关。
5. 公告轮播后台发布后，前端首页必须按轮巡方式自动展示。
6. 哈希规则必须在本地开发阶段同步实现，不能放到联调后再补。
7. 此版本为最终定稿，代码开发后不再做结构/规则大改。
